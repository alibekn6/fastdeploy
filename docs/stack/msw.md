# MSW (Mock Service Worker)

**Version:** 2.14.6 (devDependency)

## What & why

MSW intercepts HTTP requests at the network level — in the browser via a Service Worker, in Node.js via `http` / `https` patching. This repo uses it to mock the external HTTP API during local development and in integration tests, so the frontend can be developed and tested independently of the real backend. The same handler definitions are shared across both environments.

## Conventions / rules

### Handler source (single file)

All mock handlers live in `src/shared/api/mocks/handlers.ts`. URL construction uses:

```ts
const api = (path: string) => new URL(path, env.NEXT_PUBLIC_API_URL).toString();
```

This ensures handlers match the absolute URLs that the ky `http` client constructs from `NEXT_PUBLIC_API_URL`, so there is no URL mismatch between ky and MSW.

### Three consumers

| File | Export | Used by |
|---|---|---|
| `src/shared/api/mocks/browser.ts` | `worker` (`setupWorker`) | `MswProvider` (browser dev) |
| `src/shared/api/mocks/node.ts` | `server` (`setupServer`) | `instrumentation.ts` (server runtime), integration tests |

### Browser wiring (dev)

`src/app/providers/msw-provider.tsx` is a `"use client"` component. It reads `NEXT_PUBLIC_API_MOCKING === "enabled"`, dynamically imports `browser.ts` on mount, starts the worker with `onUnhandledRequest: "bypass"`, and gates `children` behind a `ready` flag so no fetch fires before MSW is active.

`app/layout.tsx` wraps `<QueryProvider>` inside `<MswProvider>`, so every client query is intercepted:

```tsx
<MswProvider>
  <QueryProvider>{children}</QueryProvider>
</MswProvider>
```

`public/mockServiceWorker.js` is the Service Worker runtime generated by `msw init public/`. It is a committed static asset; Biome is configured to ignore it.

Start dev with mocking: `pnpm dev:mock` (sets `NEXT_PUBLIC_API_MOCKING=enabled`).

### Server-runtime wiring (Node.js)

`instrumentation.ts` (Next.js instrumentation hook) starts the node server for Server Components and Route Handlers:

```ts
export async function register() {
  if (process.env.NEXT_PUBLIC_API_MOCKING !== "enabled") return;
  if (process.env.NEXT_RUNTIME === "nodejs") {
    const { server } = await import("./src/shared/api/mocks/node");
    server.listen({ onUnhandledRequest: "bypass" });
  }
}
```

The `NEXT_RUNTIME === "nodejs"` guard prevents the import from running in the Edge runtime. This is critical for e2e: the BFF route handlers (`app/api/auth/*/route.ts`) call the external API via ky — without this, server-side fetches would escape MSW and hit the real network.

### Integration tests

Tests spin up their own `setupServer()` instances (see `src/shared/api/fetcher.integration.test.ts` and `src/app/api-routes/auth.integration.test.ts`). They do not import `node.ts` — they build isolated servers per suite with `beforeAll/afterAll/afterEach` lifecycle.

## ✅ Best practices

- Add new mock routes to `src/shared/api/mocks/handlers.ts` only — never scatter handlers across the codebase.
- Always build handler URLs with the `api()` helper so they stay in sync with `NEXT_PUBLIC_API_URL`.
- Use `onUnhandledRequest: "bypass"` in `browser.ts` / `instrumentation.ts` (non-API requests pass through); use `"error"` in isolated test suites to catch typos early.
- Reset handlers with `server.resetHandlers()` in `afterEach` when overriding per-test.
- Keep `MswProvider` as a guard: `if (!ready) return null` ensures no child renders (and fires queries) before the worker is live.

## ❌ Worst practices / anti-patterns

- **Do not** call `worker.start()` outside `MswProvider` or in a Server Component — the Service Worker only exists in the browser.
- **Do not** import `browser.ts` in `instrumentation.ts` or test files; import `node.ts` for all Node.js environments.
- **Do not** hardcode URLs in handlers (e.g. `http.get("http://localhost:3000/users/:id", ...)`). Always use the `api()` helper so the base URL stays in one place.
- **Do not** add `msw` to `dependencies` — it is a dev-only tool; it belongs in `devDependencies`.
- **Do not** edit `public/mockServiceWorker.js` by hand; regenerate with `npx msw init public/`.

## Deletion checklist (when the real API is ready)

When you no longer need MSW, remove it in this order:

1. **Immediate kill-switch:** set `NEXT_PUBLIC_API_MOCKING=disabled` (or remove the env var). The app stops intercepting requests with zero code changes.
2. Delete `src/shared/api/mocks/` (handlers, browser, node).
3. Delete `src/app/providers/msw-provider.tsx`; remove its export from `src/app/providers/index.ts`; unwrap `<MswProvider>` from `app/layout.tsx` (leave `<QueryProvider>` in place).
4. Delete `instrumentation.ts`.
5. Delete `public/mockServiceWorker.js`.
6. Remove the `dev:mock` script from `package.json`.
7. Remove the `msw` devDependency (`pnpm remove -D msw`).
8. Remove the Biome `mockServiceWorker.js` ignore entry from `biome.jsonc` if present.
9. Update integration test setup: tests that imported `src/shared/api/mocks/node.ts` must now construct their own `setupServer()` with real or new mock handlers.

The ky `http` client and Zod `fetcher` are unaffected by this removal.
